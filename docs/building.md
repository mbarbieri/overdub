# Building and testing Overdub

Requirements: macOS, Apple clang with C++23 (Command Line Tools are enough), CMake 3.25+, Ninja. v1 builds `x86_64` only (ADR 0001, issue #11).

## First checkout

```sh
git submodule update --init --recursive   # external/JUCE (9.0.3), external/Catch2 (v3), external/json
```

## Build and test

```sh
cmake --preset debug            # configure into build/debug; applies the JUCE patch
cmake --build --preset debug    # builds Overdub.app, overdub_core and overdub_tests
ctest --preset debug            # runs every Catch2 test case, 12 in parallel (about 85 s; ~7 min serial with -j1)
open build/debug/src/app/Overdub_artefacts/Debug/Overdub.app
```

Use `release` in place of `debug` for an optimised build. The first build compiles JUCE once into `overdub_juce` (about 1.5 minutes on an i7-9750H); later builds only recompile what changed.

## Make targets

A top-level `Makefile` wraps the presets; it holds no build logic.

| Target | Does |
| --- | --- |
| `make app` | Initialises submodules if `external/*` is empty, builds the `release` preset's `Overdub` target, copies the signed bundle to `dist/Overdub.app`, runs `tests/packaging/verify_app_bundle.sh` on it (bundle id, version, camera and microphone descriptions, icon, `x86_64` only, no build-tree paths, `codesign --verify --deep --strict`) and prints the bundle path and signing identity. Re-running it is incremental. |
| `make install` | `make app`, then copies the bundle to `/Applications`. Override with `PREFIX=<dir>` or `DEST=<dir>`. |
| `make test` | Debug build plus the full `ctest --preset debug`. |
| `make verify-app` | Re-runs the bundle checks on `dist/Overdub.app`. |
| `make separation-model` | Runs `scripts/separation-model/install.sh`: installs the Separation model on this Mac (needs Docker; see "Separation model" below). |
| `make clean` | Removes `build/` and `dist/`. |

Signing follows "Code signing" below: `OVERDUB_CODESIGN_IDENTITY` when it is in the keychain, otherwise ad-hoc with a configure warning; `make app` still succeeds. `dist/` is git-ignored.

## Layout

- `src/<area>/`: one folder per feature area from ADR 0006 (`engine`, `plugin`, `song`, `capture`, `video`, `export`, `ui`, `app`), created when a slice needs it. Includes are rooted at `src/`: `#include "core/BuildInfo.h"`.
- `src/core/` → `overdub_core`: shared infrastructure every area links (logging, errors, RT event ring). It is not an ADR 0006 event area and has no `core.*` events: the events it emits use the areas of the callers it serves, `app.*` for launch logging (e.g. `app.log_open_failed`, `app.log_prune_failed`, `app.juce_message`) and `engine.*` for the RT event path (e.g. `engine.rt_events_dropped`).
- `src/engine/` → `overdub_engine`: the headless engine (ADR 0005). `Engine::process (inputs, numIn, outputs, numOut, numSamples, hostTimeNs)` is the one duplex callback the device and tests call; it owns the transport, the per-callback anchor (ADR 0003) and the `engine.*` RT event ring (catalog `engine/EngineEvents.h`). Each Song snapshot becomes a `RenderPlan`: one `AudioProcessorGraph` (Track nodes → Insert Chain nodes → the Track's Mixer strip → the Master's Insert Chain → the Master strip → outputs, ADR 0001, issue #33) built, prepared and warmed up off the audio thread, then handed over through an atomic pointer; the replaced plan is freed by `loadSong` or `housekeeping`, never on the audio thread. The Mixer (issue #31) is the law in `engine/MixLaw.h` (volume in dB, the −3 dB constant-power pan law for mono and stereo sources alike, mute, solo-in-place, Master volume): `Engine::setMix` writes each strip's gains into atomics of the latest plan without rebuilding it (the next block ramps to them; `engine.mix_applied` / `engine.mix_refused` at debug), and `Engine::takeMeterPeaks` reads each strip's post-fader peak. A Track at the default mix is heard at √½ on each channel. The transport renders `latency` samples ahead, so after PDC output sample n is Song sample n, and the first `latency` output samples after a seek, play, stop or plan swap are silence (ADR 0003 amendment). Test-only processors (gain, N-sample delay, echo with a tail, silence) live in `tests/engine/TestProcessors.h`. `engine::DeviceBinding` is the `juce::AudioIODeviceCallback` that calls `process()` from a live device (logging `engine.device_opened` / `engine.device_closed`); the device choice is a per-machine setting in `~/Library/Application Support/Overdub/audio-device.json` (`engine/DeviceSettings.h`), never in the Song. Tests drive the binding with `tests/engine/FakeAudioIODevice.h` and fake buffers; no test opens real audio hardware. Device changes (issue #41, ADR 0004 amendment): a stopped device calls `Engine::deviceStopped` (the transport stops, a running Pass ends where it stopped, `engine.device_stopped`); `engine::classifyDeviceChange` and `engine::sampleRateForSong` (`engine/DeviceSettings.h`) are the pure rules the app follows.
- `src/song/` → `overdub_song`: the Song model, `song.json`, migrations and the `.overdub` package with persisted history (ADR 0004). Backing Track import decodes through Core Audio's `ExtAudioFile` (`song/AudioFileDecode.h`, `song/BackingTrackImport.h`) and keeps the peaks cache (`song/Peaks.h`). The Mixer's operations (Track volume, pan, mute, solo, Master volume) are pure functions in `song/MixEdits.h`, each one undo step (`Guitar Volume`, `Guitar Pan`, `Mute Guitar`, `Solo Guitar`, `Master Volume`); `OpenSong` applies a change that only touches the mix with `Engine::setMix` instead of rebuilding the plan. The Edit timeline's Clip operations (move, trim start / end, split, delete; issue #28) are pure functions over the Song in `song/ClipEdits.h`: a Clip keeps its layer, splits keep both halves on it, and each is one undo step labelled `Move Clip`, `Trim Clip`, `Split Clip` or `Delete Clip`. Import tests encode their fixtures in the test with `ExtAudioFile` (WAV, AIFF, CAF, FLAC, ALAC, AAC). Core Audio has no MP3 encoder, so the MP3 fixture is made by `lame` (`brew install lame`); without it the MP3 test is skipped.
- `src/plugin/` → `overdub_plugin`: Insert Chain plugins (issue #33, ADR 0002 amendment). `plugin::AudioUnitLoader` discovers AU effects (AUv2 and AUv3) and creates them out-of-process and asynchronously through `AudioPluginFormatManager`; `plugin::InsertHost` keeps one processor per Insert Chain slot alive across render plans (each plan wraps it in an `engine::SharedInsertNode`), restores its state from `plugins/<sha256>.state` and captures it back (`plugin/PluginState.h`, ADR 0004 amendment). The open Song (`ui::OpenSong`) owns the host; the app's `MainWindow` owns the loader. Record rows have a minimal "+ Insert" button (slice 13 brings the chain editor). Events use the `plugin` area (`plugin.discovered`, `plugin.instantiated`, `plugin.insert_ready`, `plugin.latency_changed`, ...). `[au]` tests load Apple's AUPeakLimiter and AUDelay through the real loader; they pump the main run loop (`tests/plugin/PluginTestSupport.h`). Crash recovery (issue #40): `plugin::InvalidationWatch` (`plugin/InvalidationWatch.mm`) hears `kAudioComponentInstanceInvalidationNotification` and the host marks the AU's slot `crashed` (`plugin.invalidated`); tests post that notification themselves or call `InsertHost::pluginCrashed` with a test processor, never killing `AUHostingService`.
- `src/capture/` → `overdub_capture`: recording Passes (issue #26). The engine's `process()` copies each Armed Track's input channels into lock-free FIFOs (`engine/RecordSession.h`, started and stopped through `Engine::startRecording` / `stopRecording`); `capture::PassRecorder` drains them on an `io` thread into `audio/<take id>.wav.tmp`, and on stop renames them, writes peaks and adds the Pass, its Takes and their Clips as one undo step (`capture.pass_started` / `capture.pass_stopped`). Placement uses the device's reported latencies plus the per-machine calibration offset in `~/Library/Application Support/Overdub/latency-calibration.json` (`engine/LatencyCalibration.h`). `capture/LoopbackMeasurement.h` is the burst cross-correlation, and `capture::LoopbackRun` (`capture/LoopbackRun.h`, issue #39) the whole measuring run on the engine (bursts as a Backing Track, a Pass on input channel 0, the measurement, `capture.calibration_run_started` / `capture.calibration_run_finished`), that `overdub --selftest loopback` and the calibration flow share; `capture::measureNewestVideoTake` (`capture/ClapSelftest.h`) is the clap measurement both `--selftest clap` and the flow use. Video Takes (issue #35, ADR 0003): `capture::Camera` (`capture/Camera.h`) is the plain C++ interface over `AVCaptureSession` (`capture/AvCamera.mm`, which also asks for camera access); `capture/MovieWriter.h` writes the H.264 `.mov` through `AVAssetWriter` (movie time 0 is the first frame; frames keep their own timestamps) and `capture/MovieFrames.h` reads frames back with their motion. With a camera, `PassRecorder` writes `video/<id>.mov.tmp` from `start()` to `finish()`, then places the Video Take with `capture/VideoPlacement.h` (least-squares fit of the Pass's anchors, heard time, drift ratio) and the per-machine camera calibration in `~/Library/Application Support/Overdub/camera-calibration.json` (`capture/CameraCalibration.h`, ms per camera and output device, default 0), and adds it to the Pass's undo step (`capture.video_started` / `capture.video_stopped`). A failed movie leaves the Pass audio-only and comes back in `RecordedPass::notices`. Tests use `tests/capture/FakeCamera.h`; no test opens a camera. `[movie]` tests write and read synthetic movies through the real AVFoundation writer and reader. Recording tests drive `process()` with `LoopbackDevice` (`tests/engine/EngineFixture.h`), which echoes the output into the input after a fixed delay.
- `src/video/` → `overdub_video`: Video Take playback (issue #36, ADR 0003 amendment). `video/FrameSelection.h` is the pure pull model (heard Song sample from the latest anchor, the Video Take covering it with the newest Pass winning, movie time, the frame held across gaps, the Camera lane's spans); `video/MovieFile.h` reads a movie's frame times without decoding and decodes frames through `AVAssetReader` (forward, restarted on a seek); `video::VideoPlayback` (owned by `ui::OpenSong`) caches timings per Video Take and decodes the frame for a heard sample. Events use the `video` area (`video.movie_unreadable`, `video.frame_unavailable`, `video.video_take_shown`). `[movie]` tests write synthetic movies through `capture::MovieWriter` (`tests/video/SyntheticMovie.h`).
- `src/export/` → `overdub_export`: Export mode's mixdown (issue #37). `exporting::MixRender` renders the Song offline through its own `engine::RenderPlan` (the same graph the engine plays, so it nulls against `Engine::process()`), over the Song span (end of the last Clip) plus the plan's Insert Chain tails; it feeds the graph from Song sample 0 and drops the first PDC-latency outputs, so output sample n is Song sample n. `exporting::MixFileWriter` writes 24-bit integer WAV at the Song rate or AAC M4A at 256 kbit/s through `ExtAudioFile`; `exporting::exportMix` writes a hidden `.partial` sibling and renames it into place (`export.started` / `export.finished`), and `exporting::ExportJob` runs it on a worker thread. Shared Insert Chain plugins must not render in two plans at once, so `OpenSong::startExport` first hands the engine an empty Song and waits (`Engine::hasPendingPlan`) until the audio thread has taken it; the engine reloads the Song when the export ends. A device that stops calling back without being detached never takes it: after `OpenSong::exportAudioTimeout` (5 s) the export is given up with `ui.export_audio_unresponsive` (an Alert; issue #64). The plugins are never taken over, because the device may call back again at any moment. MP4 (issue #38): `exporting::exportMovie` (`export/MovieExport.mm`) composes the rendered mix and one Video Take with `AVMutableComposition` (sample-exact start, drift-ratio scaling; full song adds an `AVMutableVideoComposition` with a black background) and writes it with `AVAssetExportSession`; the range is `export/MovieSpan.h` (ADR 0003 amendment, issue #38).
- `src/ui/` → `overdub_ui`: the main window's JUCE Components (issue #27, issue #9 resolution): the top bar (Record · Edit · Export, keys 1–3; ⏮ ▶/■ ● with the clock and REC · PASS n; Undo / Redo naming the step), bare Record mode (one row per Track: arm, name, input picker, Monitoring; Import), Edit mode (issue #28: the Clip toolbar, the `Timeline` with Track lanes, waveforms from the peaks cache, covered-span hatching, the playhead and the Camera lane with one block per Video Take (issue #36), the Video toggle for the floating Video Preview window (`ui/VideoPreviewWindow.h` over `ui/VideoScreen.mm`, an `AVSampleBufferDisplayLayer` in an `NSViewComponent`), and, in the resizable and hideable region under the timeline, the Mixer (issue #31, `ui/Mixer.h`: one strip per Track with pan, fader, meter and M/S, and the Master strip; a fader or pan drag is previewed through `OpenSong::previewMix` and becomes one undo step on mouse up; M/S are also in the Record rows and Edit headers); drag a Clip to move it, its edges to trim, S splits at the playhead, backspace deletes), Export mode (issues #37, #38, `ui/ExportPage.h`: format WAV / M4A / MP4, for MP4 the Video Take picker (default: the Song's stored choice) and trimmed / full-song length, the span bar (`exportSpanBar`, pure), destination, progress, Reveal in Finder; `OpenSong::startExport` drives it), Notices and Alerts (ADR 0006), and the settings window's device picker and calibration panel (issue #39, `ui/CalibrationPanel.h` over `ui/CalibrationText.h`: the latency and camera calibrations in use, Measure Latency / Measure Last Clap Pass, and "Use This Calibration" for a usable result; `ui::Workspace` runs the `capture::LoopbackRun` and stores what the user accepts, ADR 0002 and ADR 0003 amendments). Components stay thin over pure functions (`ui/Commands.h`, `ui/Layout.h`, `ui/TimelineGeometry.h` (sample ↔ x at a whole number of samples per pixel, Clip hit-testing, drag → Clip operation, waveform columns), `ui/TransportText.h`, `ui/TrackRowEdits.h`, `ui/MixerGeometry.h` (fader position ↔ dB, pan drag, meter scale), `ui/UserMessages.h`, which holds the one `Error.code` → sentence table). Record mode's stage bar has the camera arm and picker (issue #35); the stage (`ui/CameraStage.mm`) hosts the camera's preview layer while the camera is Armed and a Pass runs or the transport is stopped, and Video Take playback otherwise (issue #36). `ui::OpenSong` is the open Song bound to the engine (and to the camera, `OpenSong::attachCamera`): it records Passes and finishes every Pass it starts (from the window's poll, or by waiting for the audio thread when the Song closes, the device changes or the app quits). `ui/SongFiles.h` holds what New Song, Open and Duplicate do once their dialog has a path. Monitoring is per Track and transient: the engine is given the Song with un-monitored Tracks not Armed. Events use the `ui` area (`ui.notice_shown`, `ui.alert_shown`, `ui.alert_deferred`, `ui.mode_changed`; Notice codes `ui.no_audio_device`, `ui.stop_recording_first`). UI tests follow the ADR 0005 UI amendment; `[snapshot]` tests write PNGs to `build/ui-snapshots/`.
- `src/app/` → `Overdub` (`Overdub.app`): entry point, the app icon (`app/AppIcon.png`, 1024 px with transparent margins, passed to JUCE as `ICON_BIG`, which builds the bundle's `.icns`), `MainWindow` (File menu New Song / Open / Duplicate, Edit menu Undo / Redo, the settings window; it owns the content and the `ui::Workspace`, which owns the live audio and the open Song, issue #105) and `LiveEngine`, which opens the saved (or default) device, builds the `Engine` for its output channels and buffer size, binds them (after asking for microphone access through `AVCaptureDevice`, `app/MicrophonePermission.h`), and runs the RT event drain thread and the `Engine::housekeeping` timer. `LiveEngine` is the app's `ui::LiveAudio` adapter. Its own events use the `app` area (`app.device_open_failed`, `app.device_unavailable`; issue #41: `app.device_changed` when the device is lost, reconfigured, comes back or appears, and `app.device_rate_matched` when a device is switched to the open Song's rate). The `ui::Workspace` logs `ui.device_choice_changed` when the settings window applies a new device choice, `ui.audio_reopened` when it answers a device change with a new `LiveEngine`, and `ui.clap_pass_measured`; the engine's device events (`engine.device_opened` / `engine.device_closed`) come from `src/engine`.
- `external/` → `overdub_juce`: the JUCE modules, compiled once. Our targets get JUCE through `overdub_core`, never by linking `juce::juce_*` modules directly (that would compile JUCE again and duplicate symbols).
- `tests/<area>/` → `overdub_tests`: one Catch2 executable. Each `TEST_CASE` becomes one ctest test. The one exception is `tests/separation/install_model_test.py`, the Python tests of the Separation model install script, registered as the ctest `separation model install script` and run with the host's `python3` (3.9+, standard library only).
- `scripts/separation-model/`: the Separation model install script (`install.sh`, its converter `Dockerfile`, pinned `requirements.txt` and `install_model.py`); see "Separation model" below.
- `tests/support/` → `overdub_rt_guard` (test-only dylib, never linked into `Overdub.app`): the allocation and lock guard from ADR 0005. Wrap real-time code in `REQUIRE_REALTIME_SAFE (...)` from `support/RealtimeGuardCatch.h`; it fails the test if the code allocates, frees or takes a blocking lock on this thread, including inside JUCE and libc++. It is a dylib because it interposes `malloc`-family and lock functions through dyld's `__interpose` section, which dyld ignores in the main executable. `RealtimeGuard.h` lists what it catches and what it does not.

## Loopback selftest

`overdub --selftest loopback` plays seven noise bursts through the current output device, records them on input channel 1 through the real record path, and prints one JSON line: `pass`, `offset_samples` (how late Takes land with the current calibration), `jitter_samples` (must be ≤ 5, ADR 0005), the lags per burst and the device's latencies. Use the built-in speakers and microphone, or a cable from output 1 to input 1. It exits 0 on pass and 1 on fail.

```sh
build/debug/src/app/Overdub_artefacts/Debug/Overdub.app/Contents/MacOS/Overdub --selftest loopback
```

Settings → Calibration runs the same measurement and offers to store `offset_samples` added to the offset in use (ADR 0002 amendment, issue #39). After storing it, the selftest should report `offset_samples` near 0.

## Clap selftest

`overdub --selftest clap <package>` measures the newest Video Take of a Song against its Pass's first Take. Record a Pass with the camera Armed while clapping a few times in frame, then run it on the Song's `.overdub` package. It prints one JSON line: `pass` (every clap seen is within ±½ frame), `frame_interval_ms`, `mean_offset_ms` (positive: the video is late) and per clap `song_sample`, `audio_movie_seconds`, `visual_movie_seconds` and `offset_ms`. It opens no device, and exits 0 on pass and 1 on fail. Settings → Calibration → Measure Last Clap Pass measures the open Song the same way and offers to store the camera calibration (ADR 0003 amendment, issue #39).

```sh
build/debug/src/app/Overdub_artefacts/Debug/Overdub.app/Contents/MacOS/Overdub --selftest clap ~/Music/Clap.overdub
```

## Separation model

A Separation (ADR 0007) runs the BS-RoFormer SW model, which Overdub and this repo never contain: its weights have no licence grant, so nobody may redistribute them. Each user installs it once per Mac:

```sh
make separation-model        # or: scripts/separation-model/install.sh
```

It needs Docker Desktop running, because the conversion runs in a Linux x86_64 container (PyTorch has no current Intel-macOS build). The first run builds the converter image (about 1 GB of packages) and downloads the 700 MB checkpoint; the export takes a few minutes and about 6 GB of the Docker VM's memory.

What it does, each step printed as `[step]` and a failure as `[step] FAILED: ...`:

1. `existing`: if `~/Library/Application Support/Overdub/models/bs_roformer_sw.fp32.onnx` is already a valid model (the checks of step 5), it says so and does nothing.
2. `download`: unblend 1.0.0's pinned checkpoint, `https://huggingface.co/Ryan5453/unblend/resolve/9ba75778acf1b64fc40a9ea05137a2c6af9cd1d5/bs_roformer_sw.safetensors`, into `~/Library/Caches/Overdub/separation-model/` (unblend's cache name, `56c131428745d83d.safetensors`). A cached file with the right hash is reused.
3. `verify`: its SHA-256 must be `56c131428745d83d63f72293d237fdbb56f40d8e4b6980cbcde70e28a9f7330f`; otherwise the download is deleted and the install stops.
4. `export`: `unblend.onnx.export_to_onnx("bs_roformer_sw", ..., opset_version=18, precision="fp32", static_batch=True)` (the spike's known-good recipe) into a temp folder inside the models folder.
5. `check`: the exported graph's ONNX metadata must have `architecture` `bs_roformer`, `sources` `["bass","drums","other","vocals","guitar","piano"]`, `segment_samples` 588800, `sample_rate` 44100, `stft_n_fft` 2048, `stft_hop_length` 512, `stft_win_length` 2048 and `stft_normalized` false, opset 18 and inputs `spec_real` / `spec_imag` of shape `[1, 2, 1025, 1151]`. The app checks for the model the same way, not by a file hash, because an export is not byte-reproducible.
6. `install`: one rename of the temp file to the final path. Any earlier failure leaves no file there and removes the temp folder.

Every package in the image is pinned in `scripts/separation-model/requirements.txt` (unblend 1.0.0, torch 2.14.1 CPU, onnx, onnxscript and their dependencies) on a pinned Python image, so the export is repeatable. `OVERDUB_MODELS_DIR` and `OVERDUB_MODEL_CACHE_DIR` override the two folders. Both default outside the repo, and `.gitignore` ignores `*.onnx` and `*.safetensors` anyway; delete the cache folder once the model is installed to get its 700 MB back.

Provenance: BS-RoFormer SW's original trainer is unidentified. jarredou published a repackaged checkpoint (BS-ROFO-SW-Fixed); that account has since been deleted, and the checkpoint survives only at https://huggingface.co/enerjazzer/BS-ROFO-SW-Fixed ("License: unknown"). unblend's mirror (the file the script downloads) records it as "unlicensed". With no licence grant at any step, the model is never bundled in `Overdub.app`, committed, attached to releases or downloaded by the app (`docs/research/stem-separation.md`).

## Logs

Each launch writes `~/Library/Logs/Overdub/overdub-<UTC timestamp>-<pid>.jsonl` (ADR 0006); the last 20 launches are kept. Debug builds log `debug` and up and echo every line to stderr; release builds log `info` and up. Override at launch with `OVERDUB_LOG=debug` (or `info`, `warn`, `error`):

```sh
OVERDUB_LOG=debug build/release/src/app/Overdub_artefacts/Release/Overdub.app/Contents/MacOS/Overdub
jq -c 'select(.lvl == "error")' "$(ls -1 ~/Library/Logs/Overdub/overdub-*.jsonl | tail -1)"
```

In code: `core::logEvent` (`core/Log.h`) off the audio thread; `core::RtEventRing` + an `RtEventSpec` catalog (`core/RtEventRing.h`) on it; `core::Expected<T>`, `core::logError` and `OVERDUB_CHECK` (`core/Error.h`) for failures. Tests use `core::ScopedLogCapture` and never read the log file.

## The JUCE patches

- `patches/juce-force-auv2-oop.patch` makes JUCE load AUv2 plugins out-of-process through `AUHostingService`, as it already does for AUv3 (ADR 0002), and counts those instantiations (`juce::getAudioUnitOutOfProcessInstantiationCount()`, declared in `juce_AudioUnitPluginFormatHeadless.h`).
- `patches/juce-graph-realtime-safe.patch` makes `AudioProcessorGraph::processBlock` pass the realtime guard (ADR 0001, ADR 0005). Unpatched, each node's `processBlock` runs under a blocking `ScopedLock` on its callback lock (one `pthread_mutex_lock` per node per block), and the graph reallocates its output buffer whenever the block size changes. The patch takes the callback lock with `ScopedTryLock` (a node whose lock is held elsewhere outputs silence for that block, counted by `juce::getAudioProcessorGraphBusyNodeBlockCount()` and reported as `engine.nodes_silenced`; ADR 0001 amendment) and resizes the output buffer with `avoidReallocating`. Without it the `[engine][rt]` tests fail.

Configuring applies each patch listed in `external/CMakeLists.txt` to `external/JUCE` idempotently: if it is already applied nothing happens, if it applies cleanly it is applied, otherwise configure stops with an error. `external/JUCE` shows as modified inside the submodule; `.gitmodules` sets `ignore = dirty` so the superproject stays clean.

When a patch file itself changes (a pull that edits `patches/`), a checkout that applied the old version fails configure because neither version matches. Reset the submodule and configure again: `git -C external/JUCE checkout -- . && cmake --preset debug`.

### Re-applying the JUCE patch (after bumping JUCE)

1. `git -C external/JUCE checkout -- . && git -C external/JUCE checkout <new-tag>`
2. `cmake --preset debug`. If the patches still apply, you are done.
3. If configure fails on `juce-graph-realtime-safe.patch`, redo its `OVERDUB PATCH` edits: in `juce_AudioProcessorGraph.cpp` (`GraphRenderSequence::perform`, `ProcessOp::processWithBuffer`, and the busy-node counter above `GraphRenderSequence`) and in `juce_AudioProcessorGraph.h` (the `getAudioProcessorGraphBusyNodeBlockCount` declaration at the end). Regenerate it from those two files alone: `git -C external/JUCE diff -- modules/juce_audio_processors_headless/processors/juce_AudioProcessorGraph.cpp modules/juce_audio_processors_headless/processors/juce_AudioProcessorGraph.h > patches/juce-graph-realtime-safe.patch`.
4. If configure fails on `juce-force-auv2-oop.patch`, redo its `OVERDUB PATCH` edits by hand: in `juce_AudioUnitPluginFormatImpl.h`, `createAudioUnit` runs the `AudioComponentInstantiate(..., kAudioComponentInstantiation_LoadOutOfProcess, ...)` branch for every AU and its completion increments the inline `audioUnitOutOfProcessInstantiations` counter on success; `juce_AudioUnitPluginFormatHeadless.h` declares and `juce_AudioUnitPluginFormatHeadless.mm` defines `getAudioUnitOutOfProcessInstantiationCount()`. Regenerate the patch from those three files: `git -C external/JUCE diff -- modules/juce_audio_processors_headless/format_types/ > patches/juce-force-auv2-oop.patch`. JUCE sources use CRLF line endings; `.gitattributes` keeps the patch bytes exact.
5. Commit the new submodule commit and the patches together.

## Code signing

Overdub.app is signed after every build with the keychain identity named by the `OVERDUB_CODESIGN_IDENTITY` cache variable (default `Overdub Local Development`), without the hardened runtime. A stable identity keeps camera and microphone permissions across rebuilds (ADR 0001). If the identity is missing, configure warns and the app is signed ad-hoc: it still runs, but macOS asks for permissions again after each build.

To create the identity once: Keychain Access → Certificate Assistant → Create a Certificate… → Name `Overdub Local Development`, Identity Type `Self Signed Root`, Certificate Type `Code Signing`. Then re-run `cmake --preset debug`. Check with `security find-identity -p codesigning` (a self-signed certificate may be listed as not trusted; codesign still uses it).
