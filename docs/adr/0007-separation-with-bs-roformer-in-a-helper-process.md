# Separation runs BS-RoFormer SW on ONNX Runtime in a helper process, with a model the user installs

A Separation splits one Backing Track into six new ones (bass, drums, other, vocals, guitar, piano). It uses the BS-RoFormer SW model, because in a listening test on the user's own songs it beat Demucs `htdemucs_6s` (StemDeck's model) clearly, especially on guitar, and Demucs's "without a part" mixes had audible artifacts (`docs/research/stem-separation.md`). Quality outweighs speed: a Separation is rare, and on the v1 Intel machine it takes about 4.3x the song's length (15 minutes for a 3:35 song). The model runs as an fp32 ONNX graph on ONNX Runtime 1.23.2 from C++, in a separate `overdub-separate` executable bundled in the app. The STFT, chunking and cross-fade live in that executable. The weights have no licence grant, so neither the app nor the repo contains them: a repo script downloads, verifies and converts them on the user's Mac.

## Considered Options

- **Demucs `htdemucs_6s` through demucs.cpp**: MIT code, a 53 MB model, about realtime, links straight into C++. Rejected on quality: the user heard it fall short on guitar, with artifacts in the mixes that matter for overdubbing.
- **A bundled Python/PyTorch process (StemDeck's approach)**: runs any model unchanged, but PyTorch's last Intel-macOS build is 2.2.2, every `audio-separator` release with BS-RoFormer SW needs 2.3 or later, and it means shipping or downloading a Python runtime of about 1 GB.
- **Running inference inside Overdub**: one process fewer, but ONNX Runtime can't be stopped partway through a chunk, a 6 GB peak or a crash would take down the open Song, and ONNX Runtime would join JUCE in the main link.
- **fp16 weights**: half the size (335 MB), but on an Intel CPU no faster, more memory (9.2 GB peak, from casts), and the parts move by -23 to -31 dB relative to each part.
- **Bundling the model in `Overdub.app`, or downloading it from inside the app**: seamless, but redistributes weights nobody has licensed (unblend's registry records BS-RoFormer SW as "unlicensed"; its surviving mirror says "License: unknown").

## Consequences

- **Model install.** A repo script (a Linux x86_64 container, because PyTorch has no current Intel-macOS build) downloads unblend's pinned `bs_roformer_sw.safetensors`, checks its SHA-256, exports it to ONNX with unblend, and installs it in `~/Library/Application Support/Overdub/models/`. The app checks for the model by its ONNX metadata (`architecture`, `sources`, `segment_samples`, STFT keys), not by a file hash, because an export is not byte-reproducible. Without the model, "Separate…" explains how to install it.
- **ONNX Runtime.** The build fetches the prebuilt `onnxruntime-osx-x86_64-1.23.2` (MIT) from a pinned URL, checks its SHA-256 and bundles the dylib next to the helper. 1.23.x is the last release with Intel-macOS binaries. Moving to arm64 means switching to the universal2 package or a later release. ONNX Runtime and pocketfft link only into the helper, never into `overdub_core`.
- **Pipeline.** The helper decodes the Backing Track's original file at 44.1 kHz and splits it into chunks of the graph's `segment_samples` (588800), with stride 0.75 x segment, zero padding past the end, and unblend's triangular cross-fade divided by the summed weight. Each chunk goes through a torch-compatible STFT (center, reflect padding, periodic Hann, n_fft 2048, hop 512), then the graph, then the iSTFT. The output is six 32-bit float WAVs at 44.1 kHz, each becoming a new Backing Track's original file. The Python reference and null-test script in `spikes/stem-separation/onnx/` (on the `spike/stem-separation` branch) define "correct": the helper matches it to -77 dB or better relative to the mix.
- **Process protocol.** The app starts the helper with the model path, the input file and an output folder. The helper prints progress lines on stdout and exits with zero only when all six files are written. Cancel kills the process, and the app deletes the output folder. Any non-zero exit, a signal or a missing file is a failed Separation: the Song is unchanged.
- **Resources.** Peak memory is about 6.3 GB, and the helper uses every core. That's acceptable while the modal Separation dialog blocks the app. Separation is unavailable during a Pass.
- **Tests.** Tests never run the real model (ADR 0005). They use a fake helper that writes known sines, and assert the Song change, the files, cancellation and failure handling. The C++ STFT/iSTFT and cross-fade are tested against computed expectations (STFT then iSTFT reconstructs a sine, and constant input through the cross-fade stays constant).
- **Licences.** `THIRD_PARTY_NOTICES` in the app lists ONNX Runtime and pocketfft. The model's provenance and missing licence are documented next to the install script, not shipped.
